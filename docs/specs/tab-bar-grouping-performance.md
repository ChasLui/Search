# 横向标签栏分组计算性能规格

本规格记录横向标签栏的分组优化及上游同步时需要保留的行为和验证方法。
后续跨标签栏、会话保存和 Blob 图片复制的性能复盘见
[Search 性能优化与验收规格](search-performance.md)。
2026 年 11 月 18 日验证时，代码基线为 `8c22db796284b1d9d414d1d181fa6a73b8936eb7`，
优化和测试位于该基线的未提交工作区。后续同步应以实际提交和工作区状态为准。

## 问题与目标

横向标签栏在计算标签宽度、整行宽度、溢出状态和绘制分组时，会多次查询每个组的可见标签。
原有 `visibleTabs(in:)` 每次调用都会重新遍历标签并整理分屏成员。标签数和分组数同时增加时，
一次窗口更新会重复执行这些工作，增加主线程布局时间。

一次横向标签栏布局应只对当前窗口的标签归组一次，并在本次布局的测量和绘制中复用结果。
关闭分组时使用平铺标签路径，避免为了计算行宽而整理各组可见成员。
这个结果只属于当前布局，不新增跨帧缓存、失效通知、公开 API 或会话存储格式。

## 应保留的行为

- 行顺序为固定标签、按 `tabGroups` 顺序排列的分组、未分组标签。空分组的标题仍保留位置。
- 固定标签只在固定区域显示。所属组已不存在的普通标签进入未分组区域。
- 折叠组只显示当前活动标签对应的行项。活动标签属于其他组或未分组区域时，该组只显示标题。
- 分屏开启时，一个分屏在行内占一个位置。右侧页面获得焦点时，折叠组仍显示分屏的首个标签。
  分屏关闭时，展开组和未分组区域中的分屏成员各自占一个位置，折叠组仍按活动标签决定显示。
- 标签宽度、固定区分隔线、溢出裁剪、分组内和跨组拖拽位置，与现有显示顺序保持一致。
  选中溢出区域的标签后，横向栏仍应滚动到该标签。

当前实现用 [Browser.swift](../../Sources/Search/Browser.swift) 中的 `Browser.groupedTabRow`
复用已有的 `grouping`、`pairedOff` 和 `visible` 规则，将固定标签、各组可见成员和未分组标签交给
[TabBar.swift](../../Sources/Search/TabBar.swift)。`TabBar` 使用同一结果完成测量与绘制，
并把已计算的溢出状态用于选中标签后的滚动。实现细节可随上游演进调整，上述行为和性能目标应保持。

## 同步上游时

1. 对比上游目标提交、本地分支和工作区中的标签栏相关变更，确认本规格对应的代码与测试是否仍存在。
   需要覆盖 `Browser` 的标签归组和分屏可见性，以及 `TabBar` 的测量、溢出判断、绘制和滚动。
2. 核对每次分组布局是否仍只执行一次归组，特别检查行宽计算和各组绘制是否重新逐组扫描整排标签。
   关闭分组时也应检查是否意外计算了隐藏的分组成员。
3. 若上游采用了不同实现，按本规格的行为和基准验证其效果。确认覆盖后沿用上游实现，避免重复维护。
4. 保留或迁移下列回归测试和性能基准。完成相关验证后记录上游目标提交、构建配置、运行环境和结果。

## 验证方法

使用隔离的测试 profile。先运行以下针对性测试，覆盖固定标签、未知分组、折叠组、分屏焦点、
横向拖拽、溢出滚动和快捷键。

```sh
swift test --filter TabGroupDropTests
swift test --filter RowCarryTests/testTheTopRowRevealsTheSelectedTab
swift test --filter RowCarryTests/testATabCarriedAlongTheTopWhenTabsGive
swift test --filter TabGroupDragOutTests/testCarriedOutOfItsGroupAlongTheTop
swift test --filter SplitManyTests
swift test --filter TabShortcutHintTests
```

[SpeedBenchTests.swift](../../Tests/SearchTests/SpeedBenchTests.swift) 将真实的 `TabBar`
托管在屏幕外的 AppKit 窗口中。每个操作先预热三次，再采样 30 次，记录同步更新和绘制耗时的
P50、P95，以及单独的 run-loop 统计。基准需要设置 `SPEED_OUT`，下面的命令运行 200 标签场景
并保留 JSON 输出。

```sh
speed_output="$(mktemp -t search-strip)"
SPEED_OUT="$speed_output" swift test --filter SpeedBenchTests/testStripGrouped200
printf '%s\n' "$speed_output"
```

其余场景为 `testStripGrouped600`、`testStripSmall20` 和 `testStripUngrouped200`。
比较修改前后时，分别以独立进程运行每个场景至少三次，使用同一机器、构建配置和测试负载，
同时检查 P50、P95 与样本数量。主场景的改善应超过重复运行的波动，小窗口和关闭分组的对照场景
不应有稳定回退。绝对耗时随机器和负载变化，不能把下表数值当作跨机器阈值。

项目的完整 Swift 测试入口为 `python3 Tests/run-ci-tests.py`，其中 WebKit 下载用例逐个在独立
进程运行。下载用例在 `CI=true` 时使用更长的状态等待时间。使用该设置复测时，应单独记录结果，
并保留原始完整运行的结果。
