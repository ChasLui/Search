# Search 性能优化与验收规格

本规格记录 2026 年 11 月的跨路径性能优化、复盘和后续验收要求，覆盖横向标签栏、会话保存和
Blob 图片复制。横向标签栏的完整行为契约仍以
[横向标签栏分组计算性能规格](tab-bar-grouping-performance.md)为准。

## 范围与结论

- 优先消除一次操作内重复的集合构造和查找，再根据主线程、编码、磁盘和跨进程传输的测量决定下一步。
- Swift 数组和字典已有 copy-on-write（CoW）语义；没有证据表明为 `[Tab]` 再包一层自定义 CoW
  能解决本次热点。
- 保持现有公开 API、会话 JSON 格式和 macOS 14 最低兼容版本。FlatBuffers 不是本轮验收条件；
  只有在编解码成为主要成本、读取端能直接消费缓冲区且兼容迁移方案明确时，才值得单独原型比较。
- Blob 路径仍要生成 Base64 并经过 WebKit 桥接，本轮优化不是零拷贝。

性能实现由 [PR #3](https://github.com/ChasLui/Search/pull/3) 合入 `chaslui-dev`，
合并提交为 `439657d`。本规格中的基准以 `1fb5236` 为修改前基线，修改后是该基线上应用的
性能补丁；因此数值不能当作合并提交或后续版本的重新测量结果。

## 实现与行为约束

### 横向标签栏

[TabBar.swift](../../Sources/Search/TabBar.swift) 的一次布局中应复用分屏代表项与标签 ID
查找，并按已有分组结果计数，避免为了测量把所有分组成员再次拼接成数组。查找结果只在本次布局内
使用；不得引入缺少明确失效规则的跨帧缓存。

优化不得改变固定标签、分组、未分组标签和分屏代表项的顺序，也不得改变折叠时活动分屏的显示、
分隔线、宽度、溢出滚动及拖拽位置。分组关闭、小窗口、无分屏和大量分屏都要作为对照。

### 会话保存

[Browser.swift](../../Sources/Search/Browser.swift) 构造会话快照时，应在遍历前获取一次可见
标签 ID，并在收集保留标签时收集其分组 ID，避免每个标签重复计算可见集合以及每个分组回扫全部
条目。只包含被保留标签的分组可以写入快照；标签顺序、活动项、私密标签排除和分屏恢复规则不变。

同步保存仍包括快照构造、JSON 编码和磁盘写入。额外窗口还可能触发窗口记录保存，不能将单独测试
文件的写入耗时直接等同于完整生产保存耗时。

### Blob 图片复制

[ImageMenu.swift](../../Sources/Search/ImageMenu.swift) 使用 `FileReader.readAsDataURL`
取得 Base64，避免逐块构造 JavaScript 字节字符串。仍须保留：

- 非图片 Blob 拒绝处理，Blob 超过 50,000,000 字节时拒绝处理。
- 接受数据后仍执行既有图片解码和像素尺寸检查；MIME 中有逗号时不能截断 Base64 内容。
- 保持来源 frame 和失败处理语义，并验证 macOS 14 API 可用性。

## 2026 年 11 月测量记录

环境为 Apple Silicon、macOS 27.2.1、Swift 6.4.2、Xcode 27.2，采用 Release 构建和隔离
profile。每个标签栏场景在独立进程中运行三轮；每轮每项操作预热 3 次、采样 30 次，计时包含
操作、同步布局和绘制。下表的 P50 和 P95 分别取三轮结果的中位数，单位为毫秒；它们不是跨机器
阈值，也不包括完整应用冷启动或真实显示器上的首屏延迟。

| 场景 | 切换前 P50 / P95 | 切换后 P50 / P95 | 折叠前 P50 / P95 | 折叠后 P50 / P95 |
| --- | ---: | ---: | ---: | ---: |
| 20 标签、1 组 | 6.13 / 11.81 | 5.83 / 7.74 | 29.73 / 42.85 | 29.50 / 35.15 |
| 200 标签、10 组 | 27.76 / 29.80 | 27.02 / 29.85 | 57.36 / 69.35 | 53.50 / 59.95 |
| 200 标签、分组关闭 | 29.28 / 35.87 | 27.24 / 29.84 | — | — |
| 600 标签、30 组 | 84.6 / 92.4 | 80.1 / 82.9 | 155.7 / 196.3 | 141.4 / 150.7 |

600 标签折叠和缩放的结果有改善；200 标签分组切换的 P95 基本持平。小窗口的折叠 P50 也基本
持平，不能据此宣称每个场景都有稳定收益。30 次采样的 P95 对个别慢样本敏感，后续应保留每轮原始
结果并结合波动判断。

Instruments 分配采样按同样四个场景各运行三轮。整场累计分配量的三轮中位数，以十进制 MB 计：
20 标签约 244.9 → 245.0，200 标签分组约 660.9 → 656.5，200 标签未分组约 416.8 → 399.8，
600 标签分组约 1,768.1 → 1,731.8。它是采样期间的累计分配量，不是峰值内存，也不能直接换算为
单次操作的分配量。分配跟踪本身有开销，其计时不能与未跟踪运行混用。

会话分项同样在各自独立运行的三轮中汇总，单位为毫秒：

| 操作 | 修改前 P50 / P95 | 修改后 P50 / P95 |
| --- | ---: | ---: |
| 主窗口快照 | 5.07 / 5.64 | 3.19 / 3.62 |
| 主窗口完整保存 | 7.74 / 10.44 | 5.95 / 6.46 |
| 附加窗口快照 | 5.09 / 6.36 | 3.28 / 3.65 |
| 附加窗口完整保存 | 12.98 / 18.80 | 8.89 / 9.90 |

主窗口 JSON 编码 P50 为 1.68 → 1.64 ms，独立测试文件写入 P50 为 0.55 → 0.45 ms。
这些数据支持优先减少快照构造的重复工作，尚不足以支持引入新的会话格式。

Blob 图片在隔离 Search 实例中按图片大小和实现各独立运行三次，并以约 1 ms 间隔采样 Search
及 WebContent 的 RSS。下表为三次结果的中位数，RSS 使用 MiB（1 MiB 为 1,048,576 字节）；
调用耗时是 `imageData` 的端到端调用，不包括向系统剪贴板写入图片。

| 图片字节数 | 调用耗时前 / 后 | WebContent 峰值 RSS 前 / 后 | Search 峰值 RSS 前 / 后 |
| ---: | ---: | ---: | ---: |
| 1,080,748 | 13.4 / 10.0 ms | 36.9 / 34.7 MiB | 123.2 / 123.1 MiB |
| 9,722,608 | 55.7 / 28.8 ms | 92.6 / 72.5 MiB | 154.2 / 154.3 MiB |
| 39,974,268 | 174.8 / 94.7 ms | 335.0 / 211.0 MiB | 260.3 / 260.1 MiB |

一次独立 WKWebView 模拟还覆盖了图片校验、`NSImage` 和单独命名的 pasteboard；它不等同于
在已安装应用中手动使用系统剪贴板。1 ms RSS 采样可能漏掉更短的峰值。

## 复现与验收

在同一台机器、相同 Swift 和 Release 配置下，修改前后分别运行以下场景；每个命令启动独立测试
进程。保存输出目录和测试日志，不覆盖已有 profile 或原始证据：

```sh
set -e -o pipefail
output_dir="$(mktemp -d "${TMPDIR:-/tmp}/search-perf.XXXXXX")"
printf '%s\n' "$output_dir"
for scenario in testStripSmall20 testStripGrouped200 testStripUngrouped200 \
    testStripGrouped600 testSessionWriteCosts; do
    for round in 1 2 3; do
        SPEED_OUT="$output_dir/$scenario-$round.json" swift test -c release \
            --filter "SpeedBenchTests/$scenario" 2>&1 \
            | tee "$output_dir/$scenario-$round.log"
    done
done
```

同时比较每轮 P50、P95、样本数和 Instruments 分配量；将仪器跟踪和未跟踪的延迟分开记录。
使用 Time Profiler 查看同一时间范围内的主线程调用栈，区分标签查找、SwiftUI 布局和绘制；
采样权重不是单次函数的精确执行时间。
主场景的改善应超过重复运行的波动，小窗口及未分组对照不应出现稳定回退。

会话基准必须保证不同测试顺序不影响标签数。先前多空间窗口场景留下的会话曾使主窗口恢复 30 个
标签，导致应为 600 个标签的 33 次采样变成 630 个并全部断言失败。修复后，
`testSessionWriteCosts` 在主窗口创建前和结束时写入空会话。应额外在同一测试进程中运行：

```sh
SPEED_OUT="$output_dir/session-sequence.json" swift test -c release \
    --filter \
    'SpeedBenchTests/(testOpeningWithSpaces|testSessionWriteCosts)' 2>&1 \
    | tee "$output_dir/session-sequence.log"
```

完成对应的 `TabGroupDropTests`、`SplitManyTests` 和 `RowCarryTests`，以及图片探针
`python3 Tests/copy_image.py`。图片探针需要先按项目说明构建应用；它会停止该 checkout 同名
probe 并清理专用 profile，运行前应确认其中没有需要保留的数据。验证时还应检查小窗口、分组关闭、分屏折叠、
横向拖拽、选中溢出标签后的滚动，以及图片来源 frame 和大小边界。
探针的 `T.done()` 只打印结果，不会仅因断言失败而返回非零退出码；应核对汇总为 9 项通过、
0 项失败，不能只看进程退出码。

完整 Swift 测试入口为 `python3 Tests/run-ci-tests.py`。每次记录主套件和逐进程隔离用例的
结果，不能用单项重跑覆盖原始失败记录；如延长超时重跑，应单独注明条件。不要在测试日志、PR
或公开文档中输出完整环境变量或凭据。
